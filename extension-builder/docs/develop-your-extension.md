# Develop Your Own Mind+ V2 Python Block Extension

English | [中文](develop-your-extension.zh-CN.md)

The builder handles compilation, validation, and packaging. You still need to define what the blocks look like and what Python code each block generates. At minimum, an extension needs `config.json`, `index.js`, `func.js`, and a cover image.

Start by copying `templates/blank-extension`. Make sure the blank extension builds successfully before adding blocks step by step.

## 1. File Structure

```text
my-extension/
├─ index.js                 # Block appearance, arguments, and menus
├─ func.js                  # Python code generated by each block
├─ icon/
│  ├─ blockIcon.svg
│  └─ menuIcon.svg
├─ locales/
│  ├─ en.json
│  ├─ zh-cn.json
│  └─ index.js
└─ public/
   ├─ config.json           # Extension identity and version
   ├─ cover.png             # Extension library card cover
   ├─ README.md
   ├─ requirements.txt      # Optional Python dependency information
   └─ libraries/            # Optional bundled Python/C/C++ runtime libraries
```

## 2. config.json

```json
{
  "id": "helloExample",
  "version": "1.0.0",
  "name": {
    "zh-cn": "我的扩展",
    "en": "My Extension"
  },
  "description": {
    "zh-cn": "第一个 Mind+ 扩展",
    "en": "My first Mind+ extension"
  },
  "author": "yourname",
  "cover": "cover.png",
  "main": "main.js",
  "isDevice": false,
  "sku": "",
  "mode": "python-block",
  "meta": {
    "runtimeVersion": "0.0.1"
  }
}
```

- `id`: Permanent extension identifier. Do not change it after release.
- `author`: Author identifier used in the generated directory name. Use only letters, numbers, periods, underscores, or hyphens.
- `version`: Semantic version such as `1.0.0`; increment it for every release.
- `name` and `description`: Localized name and description shown in the extension library.
- `mode`: This template uses `python-block`.
- `cover` and `main`: Normally keep `cover.png` and `main.js`.

The generated directory name is:

```text
ext-<author>-<id>@<version>
```

## 3. index.js: Define Blocks

`getInfo()` returns the extension name, colors, icons, and block list. The most important field is `opcode`, which connects a block to the method with the same name in `func.js`.

```js
{
  opcode: 'sayHello',
  blockType: BlockType.COMMAND,
  text: formatMessage({
    id: 'helloExample.sayHello',
    default: 'print [TEXT]'
  }),
  arguments: {
    TEXT: {
      type: ArgumentType.STRING,
      defaultValue: 'Hello Mind+',
      inputParams: { symbol: '""' }
    }
  }
}
```

- `COMMAND`: Command block that generates one or more statements.
- `REPORTER`: Rounded value block that returns a string or numeric expression.
- `BOOLEAN`: Diamond-shaped condition block that returns a Boolean expression.
- Argument keys such as `TEXT` must match placeholders such as `[TEXT]` in the block text.
- Do not casually change an existing block's `opcode` or argument keys after release, because old projects may no longer load.

## 4. func.js: Generate Python Code

The method name must exactly match the block's `opcode`:

```js
sayHello(generator, block, parameter) {
    const text = parameter.TEXT.code;
    return `print(${text})`;
}
```

A value block must return a Python expression together with its operator precedence:

```js
helloText(generator) {
    return ['"Hello Mind+"', generator.ORDER_ATOMIC];
}
```

To import a Python module:

```js
generator.addImport('import time');
```

Do not concatenate unprocessed user text directly. Prefer `parameter.<argument>.code` so the Mind+ generator handles string quoting and expressions.

## 5. Localization

`locales/zh-cn.json`:

```json
{
  "ext.helloExample.name": "我的扩展",
  "helloExample.sayHello": "打印 [TEXT]"
}
```

Use the same keys in `locales/en.json` and replace only the displayed text. `locales/index.js` collects the locale content, and the official template also processes localization files during the build.

## 6. Images and Third-Party Libraries

- Replace the example cover with your own `public/cover.png`.
- Replace `icon/*.svg` with your own block icons.
- Pure Python files can be placed in `public/libraries/`.
- Native libraries such as `.pyd` and `.dll` must match the target operating system and Python version.
- If the extension supports multiple Python versions, provide the matching `.pyd` for each version, as the BPX example does.

## 7. Build and Test

```powershell
powershell -ExecutionPolicy Bypass -File .\extension-builder\build-extension.ps1 `
  -ExtensionPath .\my-extension
```

After a successful build, extract the ZIP from `extension-builder/dist/`. In Mind+ Developer Mode, click **Load Test Extension** and select `config.json` from the extracted directory.

A successful build does not guarantee correct functionality. Check every block's appearance, generated Python code, dependency loading, and actual runtime behavior.

## 8. Pre-Release Checklist

- `id` and `author` use stable English identifiers.
- The version number has been incremented.
- Names and block text are complete in every supported language.
- The package contains no passwords, tokens, personal paths, or unrelated files.
- Every supported Python version has been tested.
- Upload the ZIP to a GitHub Release; do not commit it directly to the source directory.
